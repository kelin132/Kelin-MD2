# Web battle architecture notes

Sources inspected:

- Website: https://github.com/kelin132/aidoruweb1
- Bot: https://github.com/kelin132/Kelin-MD2
- Requested animated assets: https://github.com/kelin132/gmax-gifs/tree/master/Generation%208 and https://github.com/kelin132/animated-pokemon-gifs/tree/master

Verified bot behavior:

- `lib/pokemon/battleState.mjs` stores battles in an in-process `Map` keyed by `chatId`; pending challenges are another in-process `Map`. Battles expire after 10 minutes of inactivity and pending challenges after 2 minutes.
- `plugins/pokemon/challenge.js` creates a pending challenge from `.ch @user`/reply and starts a PvP battle on `.ch accept`. It currently sends WhatsApp canvas/text only and does not create a website room or persistent battle record.
- `plugins/pokemon/battle.js` handles `fight`, `items`, `item`, `switch`, `run`, and related flows in the bot process. It keeps a battle alive after a faint when the loser has another healthy party member, and ends only when no healthy Pokémon remain. It persists Pokémon HP/XP and trainer wins/losses through MongoDB, but the active room/turn state remains memory-only.
- `lib/pokemon/pokemonDb.mjs` persists Pokémon in `pokemon_owned`; records include `ownerJid`, stats, HP, moves, `imageUrl`, `backImageUrl`, `frontSpriteUrl`, and `backSpriteUrl`. Existing battle art is static PokeAPI/local sprite artwork, not animated GIFs.
- `lib/pokemon/itemState.mjs` is also in-memory and only manages repel effects.
- `lib/pokemon/trainerSprites.mjs` chooses local trainer sprites at battle creation.

Integration implication:

A web battle page cannot directly observe or advance the current bot battle state as implemented. A real shared website battle requires a persistent MongoDB-backed room/session model or an always-online bridge that both the bot and website call. The first safe implementation can add the website room contract and page, but it must not claim to mirror live WhatsApp battles until the bot challenge/battle commands publish and consume the same room state. Any real-time web synchronization should use a persistent process or database polling/change stream rather than a scheduled task.
Media repositories are available under the user account. `kelin132/gmax-gifs` contains animated Generation 8 GIFs such as `Generation 8/Pikachu.gif`, `Generation 8/Cinderace.gif`, and many form/shiny variants. `kelin132/animated-pokemon-gifs` contains numbered animated GIFs (`1.gif` through the Pokédex range). The raw GitHub URL pattern is `https://raw.githubusercontent.com/kelin132/gmax-gifs/master/Generation%208/<encoded-name>.gif` or `https://raw.githubusercontent.com/kelin132/animated-pokemon-gifs/master/<id>.gif`. No Pokémon battle audio repository was identified in the inspected list; audio should therefore be sourced from a user-provided bot asset if present or implemented as optional browser-side effects rather than copied from an unknown source.
Verified bot switch semantics from `plugins/pokemon/battle.js`: a normal switch consumes the current turn and sets the opposing trainer’s turn; after a forced faint, the trainer with the fainted active Pokémon must choose a healthy replacement, and after that replacement the prior attacker retains the next turn. The bot persists outgoing HP. `pokemon_owned` battle snapshots contain `_id`, `ownerJid`, `pokedexId`, `name`, `displayName`, `level`, `xp`, `hp`, `maxHp`, `attack`, `defense`, `speed`, `spAtk`, `types`, `primaryType`, `imageUrl`, `backImageUrl`, `frontSpriteUrl`, `backSpriteUrl`, `moves`, and `shiny`; trainer records in `pokemon_trainers` contain `party`, `inventory`, `leadPokemonId`, `wins`, and `losses`.
